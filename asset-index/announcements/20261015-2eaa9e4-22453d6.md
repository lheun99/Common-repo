## [신규] FileController — 공통 파일 업로드/다운로드 API

- 이런 때 쓰세요:
  - 업로드는 POST /api/files, multipart 필드 이름은 file
  - 다운로드는 GET /api/files/{storedFileName}
  - 다운로드 파일 이름은 원본 파일명이 아니라 저장 파일명(UUID)으로 내려간다
- 사용 예:
```js
const form = new FormData();
form.append("file", file);
const res = await fetch("/api/files", { method: "POST", body: form }).then((r) => r.json());
location.href = `/api/files/${res.data.storedFileName}`;
```
- 함께 쓰는 자산: FileStorageService, FileUploadResult, ApiResponse

> 발표 메모: 업로드·다운로드 엔드포인트가 이미 준비되어 있어 각 서비스에서 따로 만들지 않아도 됩니다.

## [신규] FileStorageService — 로컬 디스크 기반 공통 파일 저장/조회 서비스

- 이런 때 쓰세요:
  - 원본 파일명 대신 UUID 기반 파일명으로 저장 — 파일명 충돌과 경로 조작(path traversal) 방지
  - 저장 폴더는 app.file.upload-dir 설정값, 없으면 uploads
  - 저장 폴더 밖을 가리키는 파일명은 IllegalArgumentException
- 사용 예:
```java
FileUploadResult result = fileStorageService.store(file);
Resource resource = fileStorageService.loadAsResource(result.getStoredFileName());
```
- 함께 쓰는 자산: FileUploadResult

> 발표 메모: 파일 저장 로직을 각 서비스에서 따로 만들지 말고 이 서비스를 사용하세요.

---

## [신규] FileUploadResult — 파일 업로드 결과로 반환되는 정보

- 이런 때 쓰세요:
  - 원본 파일명 / 저장 파일명 / 파일 크기(byte)를 담는다
  - storedFileName은 다운로드 API 호출 시 그대로 사용
- 사용 예:
```java
FileUploadResult result = fileStorageService.store(file);
String downloadUrl = "/api/files/" + result.getStoredFileName();
```

> 발표 메모: 업로드 결과를 저장할 때 storedFileName을 함께 저장해 두면 다운로드 URL을 만들 수 있습니다.

---

## [신규] FileUpload — 업로드할 파일 하나를 고르는 입력 필드

- 이런 때 쓰세요:
  - 파일을 고르기만 하고 서버로 보내지 않는다 — 업로드는 호출부에서 직접
  - 파일은 하나만 고를 수 있다
  - 선택을 취소하면 onChange에 null이 전달된다
- 사용 예:
```tsx
<FileUpload label="첨부파일" accept=".pdf,.jpg,.png" onChange={setFile} />
```

> 발표 메모: 화면에서 파일을 고르는 입력 필드로 쓰세요. 실제 업로드는 onChange로 받은 파일을 FileController API로 보내면 됩니다.
